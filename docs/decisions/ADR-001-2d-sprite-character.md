# ADR-001 · 角色表现层改为 2D 序列帧

- 状态：**ACCEPTED（用户 2026-11-16 决定）**
- 影响：`01_DECISIONS_AND_QUESTIONS.md` 的 C06（Three.js 渲染路线）、Q02（视觉方向）、`03_3D_ASSETS_AND_ANIMATION.md` 的资产契约
- 记录者：当前主 Agent（DSH）

## 背景

M01 原定路线是 Three.js + glTF 实时角色。实测结果是：程序化建模能做到预算内（24,208 三角 / 3 材质 / 3 绘制调用），但视觉停在"毛绒手办"，达不到已签收 V05 三视图的绒感。

用户明确："我有点不想按照 3d 推进了，我觉得 2d 可以更好的还原我的概念效果"。

## 决策

角色表现层改为 **2D 序列帧（sprite）**。桌面壳（透明窗口、命中、拖动、托盘、本地存档、隐藏/退出、锁屏处理）**全部保留不变**。

## 理由

1. 76 px 显示尺寸下，2D 单帧可承载的画质上限远高于同等三角/材质预算的实时 3D。
2. 概念图本身就是 2D 图像（GPT Image 生成），2D 路线与美术资产生产链一致。
3. 运行时成本低：无实时阴影、无材质编译、无 GLB 解析。
4. 本项目已有一版可用 3D 绑定与 10 clip，可继续作为 2D 帧的**参考/占位渲染源**，前期工作不作废。

## 代价（必须写清）

- **锁视角**：不能自由旋转。
- **cursor_watch 退化**：无法连续跟随鼠标，只能离散朝向或固定动作。
- **换装/换色成本高**：每帧重画。
- **体积可能变大**：粗算 200 帧 × 152 px WebP 约 2–4 MB（现 GLB 1.27 MB），需按 clip 懒加载。
- **逐帧一致性**：若用图像生成模型出帧，同一 clip 内的帧间一致性是主要风险。
- **画质取决于画**：没有优质帧源时，2D 不会比现在的 3D 好看。

## 对原规范的修改

| 原条款 | 改为 |
|---|---|
| C06 "Three.js 为当前指定渲染路线" | 渲染层改为 2D canvas 精灵播放；Three.js 依赖移除 |
| 03 文档"glTF 2.0 / GLTFLoader / AnimationMixer" | 改为 sprite atlas（WebP）+ manifest（rects/durations/anchors） |
| 03 文档三角面/材质/draw call 预算 | 改为帧数/图集字节/显存预算 |
| 10 个 clip 命名与状态机 | **不变**，`Behavior` 与 clip 名保持一一对应 |

## 回滚条件

若 2D 帧源无法稳定产出（一致性问题无法解决），回滚到本 ADR 之前的 3D 路线；3D 资产与绑定仍保留在 `assets/pulu-kitten-rigged.glb`，不删除。
