# PULU M01 修订方案 V1.1

日期：2026-11-16。性质：实施前产品、视觉及技术方案；未开始本轮代码、模型或动画制作。原设计包保留，发生冲突的部分以本次用户要求及本修订提案为准。核心执行准则仍是仓库 CORE_PRINCIPLES.md。

## 1. 这次要解决的具体问题

前轮程序几何小猫证明了部分桌面管线，但没有达到用户期待的角色品质；增加几何细节和动画片段没有解决这一点。桌宠过大、工程进展与视觉验收脱节、把候选技术过早当成制作约束，均需要纠正。

本轮已收到并目视核对用户原概念板，旧记录“缺原概念图”失效。视觉来源见 references/PULU_original_concept.png。概念图是美术方向，不是可直接建模的精确正交三视图，也不是纹样、字体、商标权属已审查的证明。

产品定位保留：面向想养但现实中无法养宠物的人，提供轻量的自主生活与关系连续性。首轮先让一只猫可爱、自然、低打扰地待在真实桌面上。跨设备身份是长期方向，不增加M01的移动端、家园、支付或社交范围。

## 3. 原概念图的视觉基线

用户原概念板已收到并目视核对；本地方案包保留参考副本，本次不向公开仓库上传原PNG。

必须保留：银灰底与自然深灰虎斑、白胸白爪、圆脸与短口鼻、柔软蓬松轮廓、自然琥珀棕眼睛及湿润高光、粉色鼻与肉垫、红项圈和带爪印的红铃铛。光感温暖但不能把银灰毛变成棕橘色。

概念图中最关键的是毛绒和幼猫的整体轮廓、脸部层次及眼神，不是单纯“大眼睛+大脑袋”。禁止把纹样做成凸起管线、把眼球做成黑色按钮、把胡须做成粗硬白杆，或以机械拼接球体代替颊毛和口鼻。铃铛应有挂接关系和合理重量感。

图中正/侧/背姿态有透视与生成细节差异，需要美术人员统一头身、白毛边界、纹样与铃铛位置后再绑定。品牌文字、海报背景不烘进角色材质。不可直接将整张概念图贴到模型上。

### 视觉验收先于批量动画

先提交一张3/4静态效果、统一的正侧背设定、白/深/杂色背景预览，以及实际可见猫高120/140/160 CSS px的桌面样张。先看脸、轮廓、纹样和毛感是否接近原图，再检查材质数量和实时预算。每项以并排原图与输出说明差异，禁止用大幅宣传渲染代替小尺寸桌面验收。

建议评分卡：轮廓与比例、脸部/眼睛、毛感与纹样、标志配饰、小尺寸辨识度五项各1–5分；任何项≤2分都返工。评分阈值为提案，最终由用户确认方向，不把分数当客观市场结论。只需先评一个角色，不先制作10个动作。

## 4. 资产制作与显示技术分开决定

资产母版建议使用Blender完成模型、UV、纹样、材质、绑定。GPT Image用于辅助纹样/毛流素材或受控参考；先有UV再做投射、接缝修补与烘焙；生成图不自动构成可用UV贴图。毛发制作可高质量渲染，但实时版本需另做烘焙与轮廓简化，不能把离线毛发预算带进常驻桌面。

| 方案 | 好处 | 实际代价与风险 | 当前地位 |
|---|---|---|---|
| A 实时Three.js/GLB | 连续视角、头眼追踪、动画混合自然 | 小尺寸毛感、材质调用、透明毛片与常驻功耗需控制 | 原指定路线保留，作为基准 |
| B Blender预渲染透明帧/图集，桌面2.5D显示 | 容易保留柔软毛感和灯光；动作素材可控 | 视角离散，转向/过渡可能跳帧；纹理显存不一定更低 | 新建议候选，未替代A |
| C 同时交付两套完整运行时 | 覆盖更多场景 | 工作量、状态同步和测试翻倍 | 暂不做 |

建议优先对B做一个小样比较，但在同源对照通过前不切换。Three.js是已有指定路线；改变默认运行方式须记录ADR与取舍，不能因看见竞品用帧序列就悄悄改栈。Electron仍是桌面宿主候选；HyperFrames仍只考虑评审/内容生产，不承担建模或交互运行时。

### 同源对照实验（待执行）

同一个已通过静态评审的Blender角色，同一背景、角度和猫高140px，分别准备3秒待机与1次抚摸反馈。A按实际低模/烘焙实现；B建议12/20/30fps短素材比较毛边、眨眼和转场，不预先把帧率定死。

逐项记录：肉眼质量、透明毛边/黑白边、响应时延、总进程CPU/RSS、GPU或能耗代理、纹理占用、启动时延、包大小，以及30分钟观察。记录机器/系统/电源/工具口径，先热身再采样。B的未压缩RGBA显存约为帧宽×帧高×4×驻留帧数；压缩PNG体积不能当显存。A同样记录贴图、几何与绘制调用，不能仅比较JS文件大小。

选择规则：先满足视觉底线和不干扰电脑；性能按既有M01门槛实测；两者都不达标时先修资产，不通过降低视觉标准或删性能测试选“胜者”。若质量、视角和成本互有取舍，提交并排证据由产品负责人决策。本轮没有实验结果。

## 5. 桌面P0重新收敛

默认可见猫高建议140 CSS px，可调100–180；首次至少比较120/140/160。这里指模型不透明轮廓高度，不是窗口尺寸、整张帧图片或Retina物理像素。原200×190是上一轮临时窗口补救，不作为猫体尺寸验收口径。

- 左键轻点/短距离抚摸：慢眨眼、轻抬头等简短反馈；不打开主窗口。
- 拖动超过阈值：只搬动角色；释放回工作区；Esc取消；不触发摸摸或面板。
- 右键：摸摸、休息、玩具（后续）、大小、安静模式、更多设置；隐藏/退出有独立托盘入口。
- 自主行为：看、走、睡、伸懒腰、整理毛发等节奏变化；用户不互动也不罚，活动密度有上限。
- 透明区点击/滚动穿透；角色不抢输入焦点；锁屏/睡眠停表现；演示与全屏避让有明确可用入口。
- 减少动态模式关闭自主走动、突然探头及高幅度摇摆；控制面板提供键盘替代，不依赖拖放。
- 基础功能无账号、无云端模型也可用。默认不读文件、屏幕、剪贴板或全局按键，不接支付、广告或遥测。

先完成三条完整流程：初见→观察→抚摸；拖动→落脚→休息；隐藏/退出→重开→仍保留用户确认设置。喂食/玩具只作为明确用户触发的愉快互动候选，不引入饥饿债务。窗口贴边/跨屏剧情不得冒充已实现的第三方窗口识别。

## 6. 最小生命感与AI边界

渲染器只表现，行为引擎决定节奏，存档服务保存已确认偏好和有限共同事件；模型建议经过白名单、时效、预算和memoryEpoch校验后才进入行为仲裁。暂停/隐藏/拖动优先于自主动作，自主动作优先于无关AI建议。LLM不做逐帧移动、命中、冷却或坐标计算。

M01先验证关系记忆闭环：用户明确设置一个偏好→重启仍能查看/解释来源→修改/删除→旧异步结果与备份不能恢复被删内容。先前的名字和计数实现只算基础存档，不宣传为语义理解或“懂你”。自由对话、云端长期语义记忆进入P1，不因竞品有AI功能而前移。

## 8. 资产契约的最小修订

无论A/B均有独立动作清单，至少含id、版本、来源/权利、动画时长、循环、中断窗口、脚底锚点、落点、命中区域、边界与校验值。先一个角色，不建设通用MOD市场。

A增加骨架/表情映射、实际三角形/材质/绘制调用与纹理预算；B增加帧序、FPS、图集区域、每帧alpha或简化命中、透明边缘约定、贴地位置、朝向和转场规则。动画不得通过改变图片裁切导致忽大忽小、脚底漂移。资源失效后可退出，不能留下透明阻挡层。
